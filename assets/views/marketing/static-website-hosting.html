Publish a static website from a ZIP

Put your finished HTML pages and their assets in one ZIP. Pagehaven checks the files, opens a draft for editing and publishes a version at your website’s Pagehaven address when you confirm.

On this page

Prepare a finished website ZIP

Your ZIP needs an index.html file and the local files your pages load. Pagehaven finds the website at the top of the archive, inside one wrapper folder, or in a dist or build folder. If it finds several possible website folders, you choose which one to import.

Keep the ZIP within 25 MB, with at most 2,000 files and folders and 100 MB unpacked. A single file can be up to 20 MB. Check the compatible exports guide for the full limits, an example folder tree and import refusal messages.

A project’s source code is not its finished website. Build it in the original tool first, then ZIP the static output. Pagehaven never runs a build step or server code.

Import and read the file report

Upload the ZIP after signing in. Pagehaven checks the archive and the files inside it. A missing local stylesheet or script stops the import and names the missing file. Other missing assets, such as a picture, produce a warning.

The import report lists files left out, including server code, private keys, environment files and databases. Secrets and server code also raise a warning. Pagehaven keeps the original uploaded ZIP on the server, so review your archive for private files before uploading it.

Preview the draft before it goes live

Open the imported site in the editor and check its pages, images and links. Supported text, images and links can be changed there; the visual HTML editor guide explains which parts are editable.

Your draft preview uses a separate origin from the live website. Saving an edit does not change the files visitors see. Use the preview to check the draft before publishing.

Review and publish to your hosted address

Choose Publish in the editor. Pagehaven shows the changes and the address visitors will use. Confirm to create a numbered version of the website.

Your live address has the form <name>.<sites domain>, using the sites domain configured by your Pagehaven host. The website’s name and address can be changed in its settings.

Published files have editor markup and hidden sections removed. Each version’s files remain unchanged afterwards. A later edit stays in the draft until you publish again.

Put an earlier version back online

Choose “Make this version live” to point visitors at an earlier published version. Your current draft stays in place, and this action does not create another version.

To continue editing an older version, choose “Edit from this version”. Pagehaven copies it into your draft as one undoable change. Visitors keep seeing the live version until you publish the draft.

Static hosting does not run your server

Pagehaven serves the finished website files. A site that needs server code or a database will need those services elsewhere. Including them in the ZIP does not make them run.

A built website that draws its pages with JavaScript can import and publish, but Pagehaven can edit only content written in the HTML. For editable pages, export HTML that already contains the words and images you want to change.

See the Pagehaven homepage for the full editing workflow, or compare your archive with the supported HTML website exports.
