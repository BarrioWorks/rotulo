What a compatible ZIP looks like

Pagehaven imports a finished website, meaning the HTML pages and the pictures, styles and fonts they use, in one ZIP. This page shows what it accepts, what it refuses and the limits.

A ZIP that imports

This is the sample site in the homepage screenshots, shortened. Every page is an HTML file, and everything a page loads is in the ZIP with it.

What Pagehaven checks

  • index.html sits at the top of the ZIP, inside one folder, or in a dist or build folder. If several folders could be the website, Pagehaven asks which one to import.
  • The stylesheets and scripts each page links to are in the ZIP. If one is missing, the import stops and names it. Other missing files, such as a picture, get a warning.
  • Text files are UTF-8.
  • Pagehaven keeps HTML, CSS, JavaScript, JSON, text, SVG, pictures, icons, fonts, MP4 and WebM video, MP3, Ogg and WAV audio, PDF and WASM files.

Where to get one

  • A page from an AI chat. Save it as an .html file named index.html, put it in a folder with any pictures it uses, and ZIP the folder.
  • An HTML template. Download the template’s ZIP. It already holds finished pages.
  • A site someone built for you. Ask them for the built website folder, then ZIP that folder.

What Pagehaven refuses, and why

Project code that still needs a build step

Some tools download a project’s code, with files such as package.json and a src folder, instead of its finished pages. A build step turns that code into pages, and Pagehaven never runs one. It refuses the ZIP with this message:

This ZIP contains source code rather than a finished website. Export the built static website files and try again.

Shown when the ZIP holds source code

To fix it, ask the tool, or whoever built the site, for the built website folder, often called dist or build, and ZIP that.

A ZIP with no home page

We couldn’t find a website in this ZIP. It needs an index.html file at the top level or in a dist or build folder.

Shown when there is no index.html

Archives Pagehaven can’t open safely

Pagehaven also refuses ZIPs that are encrypted, that use compression other than a standard ZIP, or that are split across several files. It refuses file paths that point outside the ZIP’s folder, links to other files, and two names that differ only in capital letters.

Pages built by JavaScript

Some sites, such as a built React or Vite app, ship an almost empty HTML file and draw the page in the browser. Pagehaven imports them, and they publish and work. It shows this warning when you import one:

This website builds its pages in the browser with JavaScript. It will publish and work, but Pagehaven can only edit text and images that are written in its HTML files.

Shown after the import

In any site, Pagehaven can’t edit content that the site’s own JavaScript creates, the contents of scripts and styles, form fields, embedded frames, canvas drawings or maths.

What stays out of your hosted site

Pagehaven leaves these files out of your website and lists each one in the import report, with the reason:

  • Server code and server settings, which Pagehaven never runs.
  • Private keys, password and environment files, databases and version-control folders.
  • Archives inside the ZIP, which are never unpacked.
  • Files your computer or editor created, such as .DS_Store.
  • node_modules, package manifests and other project tooling a browser never loads.

Secrets and server code also raise a warning, so you can check that nothing private was meant to be there. Pagehaven keeps a copy of the ZIP you uploaded. Publishing copies your pages as they are, without editor markup or sections you hid, and runs no build.
